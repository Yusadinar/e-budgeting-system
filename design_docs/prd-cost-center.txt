# Tech Stack: Laravel 11, Eloquent ORM, Database Seeder

## 1. OBJECTIVE
Sistem E-Budgeting harus mengadopsi tingkat granularitas dari Master Data Cost Center sesuai hierarki SAP. Semua limitasi budget dan akses pengajuan dokumen (PPBJ, PH, IA) tidak lagi berhenti di level Departemen, melainkan divalidasi hingga ke level Cost Center Code (TM).

## 2. DATABASE SCHEMA MIGRATION INSTRUCTIONS

### A. Create Table `cost_centers`
Buat struktur tabel untuk menyimpan mapping secara spesifik:
- `id` (PK)
- `department_group` (string) -> Contoh: 'Manufacturing', 'Quality', 'Maintenance', 'PPLC', 'FIN & ACC'.
- `plant` (enum: 'IBEK', 'IKAR', 'HO') -> Keterangan: IBEK (Bekasi), IKAR (Karawang), HO (Head Office).
- `expense_type` (enum: 'FOH', 'OPEX') -> FOH untuk operasional pabrik, OPEX untuk operasional kantor.
- `cost_center_code` (string, unique, nullable) -> Kode TM dari SAP (contoh: P-902-3711). Jika di master data tertulis 'NA', izinkan null/kosong.
- `cost_center_name` (string) -> Nama detail deskripsi (contoh: 'IBEK Line A').
- `timestamps`

### B. Update Table `annual_budgets`
- Hapus field `dept_id`.
- Tambahkan field `cost_center_id` (FK constraint cascade ke tabel `cost_centers`).

### C. Update Transaksi (Proposal Harga & Internal Agreement)
- Pastikan form pembuatan pengajuan menyimpan `cost_center_id`.
- Field input UI untuk Cost Center harus otomatis terisi (Readonly) jika akun user sudah di-assign ke spesifik Cost Center.
